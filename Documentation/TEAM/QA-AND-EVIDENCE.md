# بوابة الجودة والأدلة

**نوع المستند:** إجراء تشغيلي. لا يفترض وجود وكيل QA مستقل؛ يُعيّن المراجع لكل مهمة قبل التنفيذ.

## مبدأ الاستقلال
- لا يُقبل أن يعلن المنفذ وحده أن المهمة VERIFIED.
- يمكن أن يراجع جيمي أو سوسو أو وكيل آخر المهمة، بشرط ألا يكون المراجع هو المنفذ الوحيد للتغيير.
- إذا لم يتوفر مراجع مستقل، تبقى الحالة `REVIEW_REQUIRED` ولا تُغلق المهمة عالية المخاطر.

## الحد الأدنى للأدلة
- Task ID ومعايير القبول المكتوبة قبل التنفيذ.
- commit SHA أو diff قابل للفحص.
- أسماء الملفات المعدلة وأسبابها.
- أوامر الاختبار الفعلية ومخرجاتها، مع تمييز الاختبارات التي لم تُشغّل.
- تحقق من الحالات الحدية ذات الصلة.
- بيان منفصل لحالة النشر؛ لا تساوِ بين build ناجح ونشر ناجح أو سلامة إنتاج.
- المخاطر المتبقية والافتراضات التي لم يتم التحقق منها.

## قواعد الحكم
- `VERIFIED`: كل معايير القبول اجتازت فحصًا مدعومًا بأدلة.
- `CLOSED`: التحقق اكتمل، والتوثيق وسجل العمل اكتملَا.
- `DEPLOYED`: حدث النشر فعليًا وثبتت حالته من مصدر تشغيل موثوق.
- `BLOCKED`: هناك اعتماد أو موافقة أو معلومة لازمة مفقودة.
- `FAILED`: فشل معيار قبول واحد على الأقل.
- `ROLLED_BACK`: تم التراجع والتحقق من عودة الحالة المطلوبة.

## ما لا يُعد دليلًا
- "تم الإصلاح" بلا مخرجات.
- لقطة شاشة لا تثبت مصدر القيمة.
- build ناجح لإثبات صحة البيانات أو صحة المنطق المالي.
- وجود سجل في قاعدة واحدة لإثبات وصوله إلى كل المستهلكين.
- وصف تاريخي في handoff لإثبات أن الخدمة تعمل الآن.
- نسب نجاح بلا نافذة تقييم، وحجم عينة، وتعريف للصفقات المحتسبة.

```text
Owner / Implementer / Reviewer:
Goal:
Files changed:

Acceptance criteria:
- [ ] Criterion 1 — evidence:
- [ ] Criterion 2 — evidence:

Data source / timestamp (if applicable):
Risks / unknowns:
Status: REVIEW_REQUIRED | VERIFIED | BLOCKED | FAILED | ROLLED_BACK | CLOSED
Deployment status (separate):
```
