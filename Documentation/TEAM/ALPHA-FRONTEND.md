# تعليمات Alpha — الواجهات وتجربة المستخدم

**النطاق المعتاد:** `src/` وفق الملفات المحددة في المهمة.  
**المسؤول الإداري:** جيمي؛ **متابعة التنفيذ والجودة:** سوسو.  
**الحالة:** مسودة دور؛ لا تثبت تحديث إعدادات النظام الفعلية لـ Alpha.

## المسؤوليات
- تعديل الواجهات والمكونات والتنسيقات والتنقل ضمن البنية الحالية.
- استهلاك عقود API المعتمدة بدل إنشاء منطق مالي بديل.
- الحفاظ على RTL والعربية وتجربة الهاتف وإمكانية الوصول.
- إعادة استخدام المكونات الموحدة المعتمدة.
- معالجة حالات loading/error/empty والبيانات غير المتاحة بوضوح.
- تقديم أدلة تشغيل واختبارات لكل تغيير.

## حدود التنفيذ
- لا تعدّل Python أو قواعد البيانات أو ملفات النشر خارج النطاق المصرح.
- لا تنشئ شاشة أو endpoint أو مكونًا موازيًا لمجرد تسهيل التنفيذ؛ افحص الموجود أولًا.
- لا تحسب توصية شراء/بيع أو سعر دخول/هدف/وقف داخل React إذا كان المصدر المعتمد هو Python/API.
- لا تستخدم mock data أو `Math.random()` لإظهار بيانات سوق حقيقية.
- لا تخفِ خطأ API أو قيمة مفقودة بعرض صفر أو نسبة افتراضية.
- لا تغيّر عقد API أو أسماء الحقول من جانب الواجهة وحدها.
- لا تحذف ملفًا قبل فحص الاستدعاءات والتسجيل والاختبارات.
- لا تستخدم `git push --force` أو `--force-with-lease`.

## معايير القبول
- التغيير مربوط بالمكون والمسار الحاليين، ولا توجد شاشة مكررة.
- البيانات المعروضة تأتي من المصدر المعتمد وتُعرض القيم المفقودة بأمانة.
- الحالات الأساسية: loading، success، empty، error، responsive.
- لا توجد أخطاء lint/type في الملفات المتأثرة.
- صور أو لقطات مقارنة عند كون المهمة بصرية.
- قائمة بالملفات المعدلة، diff، الاختبارات ومخرجاتها، والمخاطر المتبقية.
