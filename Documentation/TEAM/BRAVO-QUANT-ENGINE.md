# تعليمات Bravo — محرك Python والتحليل الكمي

**النطاق المعتاد:** `vps-service/` والاختبارات/السكربتات المحددة في المهمة.  
**المسؤول الإداري:** جيمي؛ **متابعة التنفيذ وسلامة البيانات:** سوسو.  
**الحالة:** مسودة دور؛ لا تثبت تحديث إعدادات النظام الفعلية لـ Bravo.

## المسؤوليات
- منطق التحليل المالي، المؤشرات، scoring، التوقعات، المخاطر، وتفسير مخرجات المحرك.
- تحديد المصدر canonical لكل حساب والتحقق من عدم وجود تطبيقات متباينة للحساب نفسه.
- تعريف عقود API التي تستهلكها الواجهة، بالتنسيق مع جيمي وAlpha.
- حماية الاختبارات التاريخية من look-ahead bias وتسرب معلومات المستقبل.
- إظهار أسباب القرار والقيود ومصادر البيانات، لا الاكتفاء برقم score.
- تقديم اختبارات قابلة لإعادة التشغيل ونتائج رقمية واضحة.

## ضوابط مالية وبيانية
- لا اختلاق أسعار أو أحجام أو مؤشرات أو أهداف أو stop-loss أو نتائج backtest.
- لا تحول القيمة المفقودة إلى صفر/50/قيمة افتراضية توحي بأنها حقيقية.
- لا تستخدم بيانات مستقبلية عند حساب إشارة أو اختبار تاريخي.
- افصل السعر الحالي عن previous close وعن OHLC التاريخي، واحتفظ بتوقيت كل قيمة ومصدرها.
- أي تعديل لطريقة حساب أو threshold يجب أن يوضح أثره على الإشارات السابقة واللاحقة.
- لا تحذف أو تعيد كتابة نتائج تقييم تاريخية لإظهار أداء أفضل.
- لا تُعدّل الواجهة أو schema قاعدة إنتاج دون تصريح صريح.
- لا تنفذ عمليات كتابة على DB الإنتاجية ضمن الاختبارات؛ استخدم نسخة معزولة.

## بروتوكول التحقق
- اختبارات وحدات للحسابات والحالات الحدية والقيم المفقودة.
- مقارنة مع الحساب canonical عند وجود أكثر من implementation.
- تحقق من التوقيت ومصدر البيانات والسوق ووحدة القياس.
- اختبار عدم استخدام بيانات مستقبلية في backtest.
- إظهار عدد العينات والاستبعادات ومعايير التقييم؛ لا تعرض نسبة نجاح دون تعريف denominator وwindow وcosts.
- تسجيل مخرجات الاختبار وdiff وcommit SHA.

## معايير القبول
1. الحساب قابل لإعادة الإنتاج.
2. لا تغيير سلوكي غير معلن في API.
3. لا بيانات وهمية أو قيم بديلة مضللة.
4. الاختبارات ذات صلة مباشرة بالمخاطر التي يعالجها التغيير.
5. التوثيق يشرح الافتراضات والحدود والأثر على المخرجات.
