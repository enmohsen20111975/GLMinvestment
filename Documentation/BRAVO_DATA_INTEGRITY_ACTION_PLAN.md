# وثيقة تكليف فريق برافو (Bravo) — خطة تأمين نزاهة البيانات وفلترة التشوهات
**المصدر:** شكاوى المالك الصريحة والمباشرة  
**الهدف:** منع البيانات الهزلية، فلترة الأسهم المقسمة الشاذة، وتغذية الرادار والداشبورد ببيانات دقيقة 100%  
**الحالة:** إلزامي وفوري

---

## شكاوى المالك الموجهة للبيانات:
1. **الداشبورد:** ظهور أرقام شاذة ومضحكة في قائمة الأكثر تحركاً مثل سهم `HALN +24400%` بسبب تجزئة أو خطأ تسوية، مما يجعل المنصة تبدو غير احترافية وهزلية.
2. **رادار السيولة:** حقول الـ API يجب أن تكون مكتملة وواضحة (RVOL، السيولة بالجنيه، حالة الـ ATR، والتصنيف الحجمي) دون أي تضارب مع واجهة العرض.
3. **بيانات تاريخ السهم والسبارك لاين:** شكوى من أن حركة الـ 7 أيام في شاشة الأسهم غير مطابقة للواقع الفعلي لتداولات السهم.

---

## خطة التنفيذ خطوة بخطوة بالملف والسطر:

### النقطة 1: فلترة الأرقام الشاذة والأسهم المجزأة في الأكثر تحركاً (Top Movers Filter)
* **الملف:** `vps-service/api/market_master_endpoints.py` (أو مسار كويري top-movers في الباك إند)
* **المشكلة:** كويري `top-movers` يأخذ التغير السعري الخام دون فحص تجزئة الأسهم (Stock Splits) أو الحدود السعرية للبورصة المصرية (الحد الأقصى اليومي الطبيعي هو 20% أو 10% حسب السهم). سهم مثل `HALN` ارتفع وهمياً بـ 24400% بسبب عدم تعديل سعر الأساس بعد التجزئة.
* **الخطة:**
  1. إضافة فلتر منطقي في استعلام الـ Top Movers:
     ```python
     # استبعاد التغيرات الشاذة الناتجة عن تجزئة غير معدلة أو أخطاء تاريخية
     WHERE ABS(change_pct) < 100.0 AND turnover_egp >= 100000
     ```
  2. تصحيح سعر الأساس لسهم `HALN` في قاعدة `stocks.db` ليطابق إغلاق الجلسة السابقة الفعلي.
* **النتيجة المطلوبة:** قائمة "الأكثر تحركاً" في الداشبورد تعرض الارتفاعات الحقيقية للأسهم النشطة (بين 2% إلى 20%) واختفاء أي نسبة هزلية تفوق 100%.

---

### النقطة 2: تثبيت واكتمال حقول رادار السيولة (/api/market/liquidity-radar)
* **الملف:** `vps-service/api/market_master_endpoints.py`
* **المشكلة:** ضمان أن كل سهم يرجع بكامل الحقول الرقمية المطلوبة لجدول ألفا دون أي نقص.
* **الخطة:**
  التأكد من أن كل كائن سهم في مصفوفة `stocks` يحتوي صراحة على:
  ```json
  {
    "ticker": "COMI",
    "price": 129.0,
    "rvol": 0.41,
    "turnover_egp": 441357117.0,
    "atr5_vs_atr20": "contracted",
    "classification": "DRY_ACCUMULATION",
    "upper_wick_pct": 0.0,
    "lower_wick_pct": 0.0,
    "close_location": 100.0
  }
  ```
* **النتيجة المطلوبة:** تغذية جدول الفرونت إند بكافة المؤشرات ليقوم بعرضها وفرزها مباشرة.

---

### النقطة 3: تأمين تغذية سبارك لاين الـ 7 أيام لشاشة الأسهم
* **الملف:** استعلامات `price_history.db`
* **المشكلة:** تغذية نقاط سبارك لاين عشوائية أو غير مرتبة تاريخياً.
* **الخطة:**
  التأكد من استعلام أسعار الإغلاق لآخر 7 جلسات تداول فعلية مرتبة زمنياً تصاعدياً:
  ```sql
  SELECT close_price FROM price_history 
  WHERE ticker = ? ORDER BY date DESC LIMIT 7;
  ```
  ثم عكس المصفوفة لتكون `[oldest -> latest]` ليرسم السبارك لاين المسار البياني الحقيقي.
* **النتيجة المطلوبة:** رسم بياني مصغر ودقيق لحركة كل سهم خلال الأسبوع المنصرم في شاشة الأسهم.
