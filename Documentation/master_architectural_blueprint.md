## 1. هوية المشروع وفلسفته الحقيقية
منصة **GLMinvestment** ليست مجرد موقع لعرض الشموع اليابانية أو سكرينر مجاني للأرقام العامة، بل هي **محطة استخبارات مالية وتداول كمي (Quantitative Market Intelligence)** تغطي:
- **البورصة المصرية (EGX)** — السوق الرئيسي والتركيز الأكبر.
- **السوق السعودي (تداول TADAWUL)**.
- **سوق الكويت (KSE)** و **سوق قطر (QSE)**.
- **الذهب، العملات الأجنبية، الكريبتو، والأسهم الأمريكية**.

### العقيدة التي بنيت عليها المنصة:
1. **صانع السوق لا يكذب في الحجم:** الأسعار تتحرك لخداع الجمهور، لكن الفوليوم الحقيقي، وتوزيع السيولة، وتموضع السعر في الدورة السنوية هي التي تكشف النوايا الحقيقية.
2. **منع "خازوق الشراء في القمة":** 90% من المتداولين يخسرون لأنهم يشترون عندما يكون السهم قد طار بنسبة 5% في قمة سنوية ظانين أنه "انفجار سعري"، بينما هو في الحقيقة تصريف ذكي (Buying Climax). وظيفة المنصة الأساسية هي كشف هذا الفخ واصطياد السهم في **نهاية التصحيح الهادئ (The Golden Dip)** عند دعوم قوية وبأقل مخاطرة ممكنة ($R/R \ge 2.0$).
3. **الصدق الرياضي أولاً:** لا أرقام وهمية، لا توقعات صعود لأسهم تتهاوى (Falling Knives)، ولا فلاتر متناقضة.

## 2. المعمارية الرباعية للخدمات الحية (Runtime & Ports)
المنصة تدار بالكامل عبر مدير العمليات **PM2** على بيئة Ubuntu/WSL، ومبنية على 4 أركان صارمة الانفصال:

```
                  ┌─────────────────────────────────────────┐
                  │          Next.js Frontend (3000)        │
                  │        (عرض فقط - Dumb Components)      │
                  └────────────▲────────────────────────────┘
                               │ HTTP Fetch & State
                               │
            ┌──────────────────┴──────────────────┐
            │                                     │
┌───────────┴──────────┐               ┌──────────┴──────────┐
│  Python Backend      │ WebSocket Push│  WS-Service (3005)  │
│  (VPS-Service :8010) │──────────────►│  (Bun / Socket.io)  │
│  [THE BRAIN - المنطق] │               │  [REAL-TIME PUSH]   │
└───────────▲──────────┘               └─────────────────────┘
            │ Internal Query
┌───────────┴──────────┐
│  Data Engine (:5000) │
│  (Python Scrapers)   │
│  [THE HEART - الشرايين]
└──────────────────────┘
```

1. **VPS-Service (البورت 8010) — The Brain:**
   - المسار: `./vps-service/main.py`
   - المكونات: بيئة بايثون كاملة تدير كل محركات التحليل الفني، مصفوفة Confluence Engine، التوقعات اليومية، والذكاء الاصطناعي المحلي (عبر Ollama طراز qwen2.5 / glm-fast على بورت 11434).
   - **القاعدة:** هو المصدر الحصري لأي حساب رياضي أو إشارة فنية تظهر على الشاشة.
2. **Data-Engine (البورت 5000) — The Harvester:**
   - المسار: `./data_engine/main.py`
   - المكونات: محركات الجلب الدورية لبيانات التداول اللحظية من TradingView و Yahoo و EODHD والسلع والكريبتو وتخزينها في القواعد التشغيلية.
3. **WS-Service (البورت 3005) — Real-Time Push:**
   - المسار: `./vps-service/ws-service/` (مشغل بواسطة Bun و Socket.io).
   - المكونات: يراقب مخرجات البايثون ويدفع التحديثات اللحظية والإشعارات إلى شاشة المتصفح بدون الحاجة لإعادة تحميل الصفحة (Polling & Push).
4. **Next.js (البورت 3000) — The Display Face:**
   - المسار: جذر المشروع `./src`
   - المكونات: واجهة المستخدم (Next.js 14 App Router / React / Tailwind Tokens).
   - **القاعدة الصارمة:** **عرض فقط (Dumb Components)**. ممنوع منعاً باتاً كتابة سطر حسابي واحد، أو تقييم إشارة، أو حساب ربح وخسارة، أو توقع أسعار في الفرونت إند. كل شيء يعرض كما يرسله البايثون.

## 5. عقيدة صانع السوق ومصفوفة الفلترة الحقيقية (No-Bullshit Trading Logic)
هذا هو المنطق الهندسي الذي يحل محل "الهبد والتجارب العشوائية":

### أ) مصفوفة الطبقات الأربع (The 4-Layer Decision Matrix)

```
[ المدخلات: بيانات السهم اللحظية + التاريخية ]
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. طبقة الموقع الهيكلي من الدورة (Macro Location Ratio)     │
│    MLR = (Price - 52W_Low) / (52W_High - 52W_Low)           │
│    - إذا MLR >= 0.90 ──► منطقة ألغام (قمة سنوية)           │
│    - إذا 0.30 <= MLR <= 0.65 ──► المنطقة الذهبية للصيد     │
└─────────────────────┬───────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. طبقة سلوك الحيتان والسيولة (Accumulation vs Climax)     │
│    - فوليوم عالي + إغلاق بفتيلة علوية في قمة ──► VETO تصريف │
│    - فوليوم عالي + شمعة ارتداد في قاع/تصحيح ──► تجميع حقيقي │
└─────────────────────┬───────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. طبقة جودة التصحيح (The Golden Dip Protocol)             │
│    - هبوط من قمة مع جفاف فوليوم: Vol_Drop <= 0.70 * AvgVol  │
│    - ملامسة دعم رئيسي (Fibo 50-61.8% أو SMA20)             │
└─────────────────────┬───────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. حارس نسبة العائد للمخاطرة (R/R Gatekeeper)               │
│    R/R = (Target - Entry) / (Entry - StopLoss)              │
│    - إذا R/R < 2.0 ──► إلغاء الصفقة فوراً (REJECT)          │
│    - إذا R/R >= 2.0 ──► اعتماد الإشارة كـ STRONG_BUY       │
└─────────────────────────────────────────────────────────────┘
```

### ب) التفريق الصارم بين 3 حالات حرجة في السوق:
1. **سهم في قمة تاريخية (All-Time High / 52W High):**  
   - **التصنيف:** `HIGH_RISK_EXTREME`.
   - **القرار:** ممنوع إعطاء شراء لمجرد شمعة خضراء بنسبة 3%. الشراء مسموح فقط في حالة واحدة: **اختراق صريح فوق المقاومة السابقة + إعادة اختبار ناجحة (Retest) لمدة 3 أيام مع فوليوم متناقص في الهبوط**.
2. **سهم مخلص تصحيح (Golden Dip - الصفقة الألماظ):**  
   - **التصنيف:** `CONFLUENCE_DIP_BUY`.
   - **القرار:** هذا هو السهم المستهدف؛ سهم نزل 5% إلى 12% بهدوء (بياع ضعيف)، لمس دعماً معتبراً، وأول شمعة خضراء ظهرت بفوليوم حوت. الدخول هنا مثالي لأن وقف الخسارة قريب جداً (تحت قاع التصحيح بـ 1%) والهدف قمة سابقة (R/R يتجاوز 3:1).
3. **السكين الساقطة (Falling Knife):**  
   - **التصنيف:** `DISTRIBUTION_VETO`.
   - **القرار:** سهم يكسر دعومه بفوليوم، أو سهم هابط وفوليومه متزايد. **ممنوع بتاتاً وضع أهداف صاعدة له**، والتوصية الإلزامية هي `HOLD` أو `AVOID`.

## 6. معمارية الحالة التراكمية (حل معضلة الـ 25 سنة والـ 290 سهم)
### المشكلة الكارثية السابقة:
إذا قام المحرك بفحص 1.3 مليون صف وتاريخ 25 سنة لـ 290 سهماً في كل دورة تحديث (كل 5 دقائق)، فإن المعالج سيتجمد وتستهلك الذاكرة ويهنج السيرفر!

### الحل الهندسي المعتمد (Incremental Warm State Architecture):

```
       [ Cold Boot - يتم مرة واحدة فقط عند بدء التشغيل أو في إغلاق السوق ]
      ┌──────────────────────────────────────────────────────────────────┐
      │ قراءة 1.3M صف تاريخي ──► استخراج الثوابت الهيكلية لكل سهم:     │
      │ (52W High, 52W Low, SMA200, 20-Day Avg Volume, Major Supports)   │
      │ ──► حفظها في جدول خفيف وسريع في الذاكرة (stock_macro_state)      │
      └────────────────────────────────┬─────────────────────────────────┘
                                       │
                                       ▼
       [ Hot Loop - يتكرر كل 5 دقائق أثناء الجلسة ]
      ┌──────────────────────────────────────────────────────────────────┐
      │ سحب شمعة اليوم اللحظية فقط (1 صف لكل سهم)                       │
      │ ──► مقارنة السعر بالثوابت المحفوظة مسبقاً (Memory Lookup)         │
      │ زمن المعالجة: أقل من 30 ميلي ثانية لكل السوق مجتمعاً!            │
      └──────────────────────────────────────────────────────────────────┘
```

بهذه الطريقة، يتحول التعقيد الحسابي من $O(N \times 25 \text{ Years})$ المرهق، إلى $O(N \times 1)$ الخارق للسرعة!

## 7. هندسة الإبهار اللحظي (Micro-Pulse كل 2.5 دقيقة بدون تزييف السعر)
### الرؤية التجارية vs الأمان الرياضي:
البيانات الحقيقية ترد كل 5 دقائق. نريد إعطاء المتداول إحساساً بأن المنصة "حية، استباقية، وسريعة" دون الوقوع في جريمة تزييف أسعار الصفقات (Repaint Trap).

### كيفية التنفيذ السليم:
1. **ممنوع تزييف سعر الإغلاق اللحظي:** إذا توقعت أن السعر أصبح 101 وجاء التحديث الحقيقي 99، ستحدث قفزة سعرية للخلف تفضح النظام.
2. **البديل العبقري (نبض السيولة + الرينج المتوقع):**
   - **في الدقيقة 2.5 (منتصف البار):** ترسل خدمة `ws-service` عبر الـ WebSocket حدثاً باسم `LIQUIDITY_PULSE` يعرض حركة أنيميشن لمؤشر ضغط المشترين والبائعين (Order Flow Pulse).
   - **عرض نطاق الحركة المتوقع (Predicted 5-Min Corridor):** عرض قناة استباقية:  
     *"النطاق المتوقع للشمعة الحالية: [45.20 - 45.80]"*. عندما تنتهي الـ 5 دقائق وتأتي الشمعة الحقيقية داخل الرينج، ينبهر المستخدم بدقة المنصة التنبؤية.
   - **شريط أحداث الرادار الحية:** تدفق رسائل استخباراتية سريعة مثل: *"رصد امتصاص عروض في سهم COMI"* لجعل الشاشة نابضة بالحياة دائماً.

## 8. خطة العمل التنفيذية وتكليفات الفرق (Alpha vs Bravo)

### أ) تكليف فريق Bravo (بايثون والمحركات الخلفية):
1. **المرحلة 3 (Caller Refactoring):**
   - ربط ملفات `daily_predictor.py` والـ Endpoints بمحرك `vps-service/core/unified_scanner.py` الموحد الذي تم بناؤه في Commit `8ddf060`.
   - إضافة مصفوفة الـ `Macro Location Ratio` داخل `unified_scanner.py`.
2. **المرحلة 4 (Dead Code Execution):**
   - إعدام وحذف الـ 68 دالة المكررة للـ ATR و RSI و MACD في الملفات القديمة.
   - حذف السكريبتات الميتة الفائضة في مجلد `scripts/`.
3. **اعتماد الـ Incremental State:**
   - تطبيق جدول الذاكرة التراكمية لتفادي مسح الـ 25 سنة في كل تكرار.

### ب) تكليف فريق Alpha (واجهات المستخدم `src/`):
1. **المرحلة 4 (Page Refactoring):**
   - البدء فوراً في استبدال الأكواد المكتوبة يدوياً في الصفحات باستخدام المكونات المركزية الثلاثة الجديدة:
     `<TrendIndicator>` و `<StockCard>` و `<MarketTable>`.
   - التأكد من أن كل الشاشات تعرض فقط البيانات الواردة من الـ API دون أي حسابات فرونت.
2. **تفعيل الـ Micro-Pulse في الواجهة:**
   - ربط كروت الأسهم بالنبض التفاعلي لخدمة الـ WebSocket.

## 9. مصفوفة الاختبارات المعيارية والاعتماد الحتمي
قبل إطلاق أي كود للإنتاج، يجب أن يجتاز المعسكر الرباعي التالي:

| الاختبار | الشرط الحتمي للنجاح | طريقة الفحص |
|---|---|---|
| **باك تيست 500 يوم حقيقي** | عينة سنتين كاملتين (2024 - 2026) لأسهم EGX30 بـ Win Rate $\ge 60\%$ و Profit Factor $\ge 1.8$. | تشغيل الباك تيست على `price_history.db` |
| **كاشف مصائد القمم (Peak Traps)** | نسبة كشف فخاخ الشراء في القمة والتصريف $\ge 85\%$. | فحص أداء السكنر على فترات القمم التاريخية |
| **صيد التصحيح (Dip Buy)** | نسبة نجاح صفقات الارتداد من الدعم مع وقف خسارة محكم $\ge 70\%$. | عزل صفقات الـ Golden Dip واختبارها |
| **اختبار سرعة الأداء وموارد السيرفر** | فحص كامل الأسواق في زمن $\le 3$ ثوانٍ وذاكرة RAM مستهلكة $\le 500$ ميجابايت. | قياس زمن الـ Scan ومراقبة PM2 Metrics |

## 10. المحاذير الحديدية والقواعد الذهبية غير القابلة للنقاش
1. **ممنوع Force Push** على مستودع Git تحت أي ظرف.
2. **ممنوع تكرار الحسابات:** أي مؤشر فني أو معادلة تُحسب في مكان واحد فقط داخل موديول مركزي.
3. **ممنوع التوصيات العشوائية:** سهم نازل سقوط حر = ممنوع أهداف صاعدة.
4. **ممنوع أرقام وهمية:** لا Mock Data في بيئة التشغيل أو الحسابات.
5. **ممنوع Force Buying في القمم:** السهم الصاعد 5% في قمة سنوية يوضع تحت المراقبة والتأكيد، ولا يُنصح بشرائه للمستخدمين كفرصة مؤكدة.
